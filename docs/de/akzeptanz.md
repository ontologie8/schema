# Akzeptanzkriterien

Der komplette P0–P6-Scope liegt in der [Roadmap](../../roadmap/de/personen-nachlass-roadmap.md).

| ID | Prüfkriterium |
| --- | --- |
| AC-01 | Alle Ideen und Haus-/Auto-/jährliche-Aktien-Beispiele mit beiden Sterbereihenfolgen erhalten. |
| AC-02 | Phasen, Abhängigkeiten, überprüfbare Ergebnisse und offene Designentscheidungen dokumentiert. |
| AC-03 | JSON Schema, NetworkX, RDF/Turtle/SHACL und Graph-DB-Gate getrennt; ein führendes Modell. |
| AC-04 | Keine produktiven Mandatsdaten in Git; belegte Beziehungen, deterministische Berechnung und notarielle Prüfung. |
| AC-05 | Gantt-Verknüpfung und passende Remote-CI geprüft. |
| AC-06 | Eine Person mit mehreren zeitabhängigen Rollen; Beteiligung wird nicht aus dem Amt abgeleitet. |
| AC-07 | Unternehmensvermögen, private Anteile, Darlehen und Bürgschaften getrennt; keine Doppelzählung. |
| AC-08 | Tod/Ausfall/Amtsende, Anteilserbfolge und Organ-/Vertretungsnachfolge getrennt; keine automatischen Berechtigungen. |
| AC-09 | Familien-, Beteiligungs- und Vertretungsansicht nennen Stichtag, Quellen und offene Tatsachen. |
| AC-10 | Deutsche Projektpflege in Phase 1; mehrsprachige Werte sind im allgemeinen Modell ohne neue Feldstruktur möglich. |
| AC-11 | BCP-47-Sprachkennzeichen am Textwert; Sprache, Land und Rechtsraum getrennt; kein geratenes Deutsch bei fehlender Sprache. |
| AC-12 | JSON-/RDF-Abbildung erhält Text, Sprache, Identität und Mehrfachwerte; Schriftrichtung wird bei Bedarf verlustfrei behandelt. |
| AC-13 | Dokumentfassungen und Übersetzungen besitzen eigene Identität, Versionsbindung, Herkunft und Status; kein automatischer Vorrang. |
| AC-14 | Ereignis-/Gültigkeitszeit und Erfassungsrevisionen sind getrennt; historische Abfragen nennen fachlichen und Wissensstichtag und erhalten Korrekturen. |
| AC-15 | Kaufpreis, Beobachtung, Wertart, Bewertungsstichtag und Quelle bleiben getrennt; konkurrierende Bewertungen werden nicht still überschrieben. |
| AC-16 | Bestandsbewertung verbindet zeitlich passende Menge, Kurs, Markt-/Stückbasis und Währung; unbekannte Eingaben bleiben offen. |
| AC-17 | Prognosen und Empfehlungen nennen Kontext, versionierte Methode und Eingaben; bei Prognosen bleiben Zielzeit und Berechnungszeit getrennt; keine Änderung bestätigter Historie. |
| AC-18 | Zeitpräzision, offene/unbekannte Grenzen, Halbintervalle und Revisionskonflikte sind definiert; Abbildung erhält diese Bedeutung. |
| AC-19 | Gemeinsamer Modellkern, Fachmodule, Anwendungsfall-/Speicherprofile und externe Versionsübernahme sind getrennt; Auto, Aktien und Kleidung nutzen denselben Kern. |
| AC-20 | Erbausschlagung aus einem festgehaltenen `ontology`-Quellstand als synthetische Prüfungen: Vollzugswege, getrennte Personen, Kenntnis-/Eingangsnachweise und offene Vertretungs-/Genehmigungs-/Annahmerisiken; keine automatische Rechtsentscheidung, JSON-/RDF-Rückweg erhält die Bedeutung. |

Die Kriterien sind die Prüfziele der geplanten Umsetzung.
